# 软著申请材料生成工具包

[English](README.md) | [简体中文](README.zh-CN.md)

> 把「软著申请材料制作」沉淀成一条可复用基线：改配置 → 跑脚本 → 交付。

> **说明。** 这个仓库里带有具体公司的内容 —— 品牌文案、标志、资源路径。真正值得拿走的是版式、动效和代码。发布前请先替换内容。


## 这是什么

这不是一套文档模板。模板依然要你每次手工拼出三份材料，配着同样繁琐的格式活。

这里是一份配置文件驱动三份产出。登记表、源代码鉴别材料、使用说明书都是生成出来的，所以第二次申请做的是改配置，不是做文档。

## 为什么开源

我们做了一次软著申请，发现大部分活儿是机械的：结构一样、内容不同、要在三份文档里重复。

申请流程对谁都是一样的，所以这是一个适合公开的工具。里面附的案例是示例，可以替换掉。

## 里面有什么

- **一份配置驱动三份交付物：**
  - 软件开发基本信息表，`.docx`
  - 程序鉴别材料 —— 源代码前 30 页加后 30 页，PDF
  - 文档鉴别材料，即使用说明书，PDF，含截图
- **截图自动生成**，适用于带界面的软件。
- **模板**，基本信息表和使用说明书都带占位符版本。
- **一份写明的工作手册**，把流程从头到尾讲一遍。
- **一套完整的落地案例** —— 配置、源 markdown、三份产物、截图全都在，能看清每份产物该长什么样。

## 环境要求

Python 3 · python-docx · PDF 生成依赖

## 怎么开始

1. 复制一份配置文件，填上软件名、著作权人、代码路径、界面模块、环境信息。
2. 让说明书 markdown 指向你的文档和截图目录。
3. 按顺序跑四个脚本：基本信息表、源代码材料、截图、使用说明书。

仓库 README 里把每一步和具体命令都写清楚了。

## 注意与边界

1. **源代码材料是按页算的。** "前 30 页加后 30 页"这条规则预设了一定的代码量。代码特别少或者特别多的时候，看一下它跑出来是什么样。
2. **截图需要界面能跑起来。** 没有界面的软件，这一步用不上。
3. **格式要求是行政规定。** 这里说了算的是登记机关的要求，不是这个工具包。
4. **附带案例是公司内容。** 发布前替换掉。
